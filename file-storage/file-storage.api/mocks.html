File Storage — Admin Console

Screen mocks for the file-storage module's ops / compliance admin surface, each mapped to its endpoint. Reads gated @RequiresAction('file.view'); deletes 'file.delete'; category edits 'file.category.manage'. Non-platform actors see and edit only their own tenant. This is not the per-entity upload/view/download surface — that stays in the vertical's controllers. Screens marked Proposed are legitimate but unserved.

By design. Infected files are rejected at attach and never stored, so there's no quarantine. The blob has no RLS behind it — AttachmentService enforces the tenant boundary on every path, and this console inherits that.

Orphans

GET/files/orphansLive

File records with zero attachments — usually a persistence write that half-failed, or an entity deleted without detaching its files. Storage cost, not a correctness bug.

Gate: file.view. Filter olderThan excludes a just-uploaded record mid-attach.

Retention & Legal Hold

GET/files/retention POST/files/:id/holdProposed

Files past their category's declared keepForDays — candidates for a lifecycle job — and files under legal hold that must not be deleted regardless.

Missing API. FileCategory.retention is stored and never read. Proposed: GET /files/retention → records past their retention window (grouped by category), a lifecycle job that acts on them, and a legal hold flag — POST /files/:id/hold / DELETE /files/:id/hold — that makes DELETE /files/:id and any sweep refuse.
