Authorization — Access Console

Screen mocks for the authorization module's console — who can do what, and changing it. One console for two audiences: a platform admin sees every tenant and the platform roles; a tenant admin sees and changes its own tenant only — the API forces it, the screens just don't offer the rest. Any signed-in user gets My access.

Why this console exists. Access drifts quietly: people collect roles nobody takes back, a contractor's role outlives the contract, someone lends an approval while on leave and forgets it. And a missing grant only shows up as somebody's "it says I don't have permission". This is where you see who holds what, why someone can or can't do something, what's about to lapse, and who keeps getting refused.
The model. A role grants a set of actions; a user holds roles in a tenant (or globally — every tenant — for platform staff), optionally until an expiry. A user can lend some of their own actions to a colleague in their tenant until a date (a delegation) — it grants only while the lender still holds them. Each action is tenant-scope (acts on one tenant's data) or platform-scope (reads or changes every tenant's — a rate-limit log, running a job); a role holding a platform action is assigned globally only, by a platform admin. Role definitions ship with the app — this console assigns, lends and describes; it never edits what a role grants.
