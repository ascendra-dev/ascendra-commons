Notification — Admin Console

Screen mocks for the notification module's admin surface, each mapped to its endpoint. Reads gated @RequiresAction('notification.view'); config writes 'notification.manage_config'; test send 'notification.test_send'. A non-platform actor may only touch their own tenant's rows (a tenant_id IS NULL deployment default is platform-admin only). Screens marked Proposed are legitimate but unserved.

Credentials never leave the server. The config surface returns which (channel, tenant) pairs have a credential, never the values. Stored content is opt-in (storeContent) and pruned with its delivery row — not a long-retention archive.

Bounces & Suppressions

GET/notifications/suppressionsProposed

Recipients that repeatedly bounce or complain — so the app stops hammering a dead address (and its sender reputation) every send.

Missing API. Bounces are recorded per delivery row but never aggregated into a list, and Notifier doesn't consult one. Proposed: a commons_notification_suppression table (recipient, reason, since, source), populated from webhook bounce events, checked by Notifier before send; GET /notifications/suppressions + DELETE /notifications/suppressions/:ref to clear a false positive.
