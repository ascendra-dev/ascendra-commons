Rate Limiting — Admin Console

Screen mocks for the rate-limiting module's admin surface. Every read is gated @RequiresAction('rate-limit.view') — an ops/security persona. No tenant scoping: a rejected request usually wasn't signed in, so it has no tenant.

Why this console exists. A 429 used to vanish with no trace anywhere. If a public endpoint — a payment link, most concretely — is being hammered, this is where it shows.
What a row is. The recorder counts rejections in memory and writes every 10 seconds, so the log holds one row per route, source, limit and minute — "203.0.113.7 was turned away 280 times on /pay/:token in 09:40", not 280 rows. Rejections arrive up to ~10s late. A row whose minute is still running keeps counting.

  • Source is what the throttler counted by — an IP, behind one trusted proxy. Clicking it filters the list to that source. Copyable.
  • Seen is the first and last rejection inside the minute — a burst reads as a narrow span, a steady drip as a wide one.
  • Correlation only when the caller sent one (a well-behaved client, rarely an attacker) — it opens the Trace sheet. No link otherwise.
  • No "of N" total: the list pages by cursor with no count query, like audit's. The Overview carries the totals.
  • Route and Period come from the URL, so the Overview's links land here pre-filtered.
